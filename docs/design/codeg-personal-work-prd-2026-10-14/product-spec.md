# CodeG 产品功能文档：个人工作代理台

**文档日期：** 2026-10-14（Asia/Manila）  
**读者：** Mack（产品决策）及后续设计 / 工程对齐  
**依据：** `codeg-personal-work-ux-2026-10-14` 调研结论 + CodeG 现有能力；不编造竞品价格或未证实数字。  
**配套：** 同目录 `wireframes.md`（界面草图）、`scenarios.md`（场景旅程）、`index.html`（可本地预览）

---

## 1. 产品一句话与目标用户

### 一句话

> **CodeG = 个人工作代理台**：默认像 Cowork / Work——能聊、能交办、能定时；打开代码仓库时再露出 git 级联与多 coding agent。护城河留下，门面换软。

### 目标用户

| 画像 | 他们要什么 | CodeG 怎么接住 |
|------|------------|----------------|
| **个人知识工作者**（也会写一点代码） | 调研、周报、收件箱分诊、定时简报、把结果写进自己的知识库；不想看见 worktree / merge | 交办为主路径；交付预览；业务文案；Wiki 落点 |
| **会写代码的人**（主力仍是开发） | 同一套深度：多代理、diff、worktree、审阅合并；同时希望「非编码杂事」也别换工具 | 打开代码仓库时完整露出现有 ACP / git 流水线；日常杂事走同一 Composer |

**一句话验收（产品体感）：**  
非开发同事只靠中文描述，能完成「调研并写成周报 + 每天定时更新」，全程不看见 worktree / merge；开发同事仍一键回到现有 To-do 合并流。

## 2. 设计原则

1. **少模式税**  
   同一 Composer 入口。短问直接聊；多步 / 产出物 / 定时一键「转为交办」。不强迫用户先选 Chat / Work / Agent。

2. **交办为主**  
   「描述结果 → 离开 → 回来审」是默认主路径，不是消息上的小彩蛋。进度可见、可中途改方向、做完来找你。

3. **审批有档**  
   三档：谨慎 / 平衡 / 放开。默认「平衡」——读自动，写 / 发 / 删才问。消灭步步点 Allow 的疲劳。

4. **交付预览优先**  
   通用任务 Review 主视图是 MD / 表格 / 文档预览；diff 收进「变更明细」。编码任务仍以 live diff 为一等公民。

5. **非编码隐藏 git 术语**  
   隔离工作区 → 待你确认 → 采纳。引擎可继续用 worktree，界面不说。

6. **深度能力进阶露出**  
   `@` 多代理、Infinite Canvas 是护城河，不是新手默认首页。单会话 + 交付预览先站住。

7. **做完来找你**  
   桌面通知 + 可选飞书 / 微信 / Telegram；托盘统一「进行中 / 待你确认 / 失败」。

8. **本机依赖说人话**  
   交办若依赖本机文件 / 浏览器，标明「桌面需在线」；纯云 / server 任务才暗示可关电脑。移动端以进度、问答、批准为主，不承诺完整本机 Agent。

## 3. 信息架构与主导航

### 3.1 顶层结构（建议）

```
工作台（Home）
├── 今日 / 进行中托盘
├── Composer（统一入口）
├── 最近会话
└── 待你确认（审批 / 交付）

交办（To-dos）
├── 待办
├── 执行中
├── 待你确认
└── 已交付

知识（Wiki）——最小可用
├── 最近整理
├── 导入 / 落点
└── 与交办联动的页面

频道（已有飞书 / 微信 / Telegram）
├── 入站消息分诊
└── 完成回传设置

进阶（默认折叠）
├── Canvas
├── 多代理配置
└── 打开代码仓库后的 git / agent 深度能力

设置
├── 审批档位（谨慎 / 平衡 / 放开）
├── 通知（系统 + 频道）
└── 定时 / Automations
```

### 3.2 导航原则

- **默认落点 = 工作台**，不是空白 Canvas，也不是「选一个 coding agent」。
- 看板列名用业务语言：**待办 / 执行中 / 待你确认 / 已交付**（编码仓库内可保留 Merge 文案作为同义高级标签）。
- 「编码」不是顶栏第三模式，而是**打开代码仓库上下文后自动露出的能力层**。

### 3.3 与六种日常模式的映射

| 日常模式 | 主导航落点 | 是否新手默认 |
|----------|------------|--------------|
| 快聊 | Composer 短问 | 是 |
| 交办并回来 | Composer「转为交办」+ 交办看板 | 是 |
| 例行 / 定时 | 交办 schedule + 通知 | 是（轻量） |
| 项目 + 本地文件 + Wiki | 工作台项目感 + Wiki | 是（最小） |
| 多代理 | @ / Canvas | 进阶 |
| 行内改 | Review 预览上划选 | 后做 |

## 4. 功能规格

以下按模块写清：**目的、用户价值、主流程、边界、与现有 CodeG 能力关系**。

---

### 4.1 统一入口 Composer（聊 / 交办）

**目的**  
把「快问」和「交办」收进同一输入框，消灭入口分裂。

**用户价值**  
不用先想「我现在该开 Chat 还是 Task」；短问秒回，长活一键交办。

**主流程**

1. 用户在工作台或会话底栏打开 Composer。  
2. 输入自然语言（可 @ 文件 / Wiki / 频道上下文）。  
3. 系统启发式识别：
   - 短问 / 解释 / 改一句 → **直聊**（当前会话流式回复）。  
   - 整理、生成报告、多步、定时、会改外界 → 提示 **「转为交办」**（大按钮，不是藏起来的菜单项）。  
4. 用户确认交办后，生成 To-do，进入执行中；会话保留交办卡片入口。  
5. 已有「从消息创建 task」能力升为**主路径**：消息旁「转为交办」与 Composer 提示同权。

**边界**

- 不强制三分顶栏（Chat | Work | Codex）；若保留「编码」入口，放在打开仓库后或进阶菜单。  
- 启发式可错：用户随时可手动「转为交办」或「仅本次对话」。  
- 切换显式高级模式时，文案说明是否新开上下文（避免静默丢上下文）。

**与现有能力**  
复用统一 ACP 会话、消息队列、从消息创建 task；产品叙事上把「转为交办」做大。

---

### 4.2 交办 To-do / 进度 / 通知

**目的**  
让「描述结果 → 离开 → 回来审」成为可信体验。

**用户价值**  
不用盯屏；随时知道走到哪一步；完成或卡住会来找我。

**主流程**

1. 交办创建：标题（结果导向）+ 完成标准 + 可选截止 / 定时 + 工作区范围（文件夹 / Wiki / 仓库）。  
2. 执行中：统一「当前步骤」组件展示里程碑（来自 `task_progress` / workflow overlay / status strips 的收束）。  
3. 全局托盘：`进行中 (n)`、`待你确认 (m)`；点击直达。  
4. 终态通知三类：**完成 / 需确认 / 失败**（系统通知 + 可选频道）。  
5. 用户可中途改方向（补充说明进入队列或当前回合——见消息队列产品说明）。

**边界**

- 依赖本机的交办：UI 标明「需桌面在线」；关闭桌面后的行为不假装仍在跑（除非已走 server / 云 worker——该能力属后做）。  
- 移动端：看进度、答审批、轻量改方向；不承诺本机文件代理。

**与现有能力**  
To-dos、`task_progress`、看板 badge、Automations、桌面 / server / mobile。统一叙事与托盘，而不是再造一套任务系统。

---

### 4.3 审批三档与计划卡

**目的**  
既可控又不累死用户。

**用户价值**  
默认顺滑；敏感动作仍有闸门；会改外界的事先看计划再跑。

**主流程**

| 档位 | 行为 | 适用 |
|------|------|------|
| **谨慎** | 工具调用几乎都问 | 高敏感目录、演示环境 |
| **平衡（默认）** | 读自动；写 / 发 / 删 / 外发询问 | 日常个人工作 |
| **放开** | Skip 权限（强警告） | 可信沙箱、用户明确授权的长跑 |

1. 设置或会话级可调档；长时间交办建议默认平衡。  
2. **会改外界**的交办（写文件、发频道、改日历等）默认先出 **计划卡**（plan-approval）→ 用户同意 → 执行。  
3. 权限提示复用现有 permission / ask-question 卡，文案用人话描述「要做什么」，可展开参数细节。

**边界**

- 删除 / 不可逆操作在平衡档仍强制确认（对齐业界「删文件强制确认」习惯）。  
- 不引入第四、第五种用户可见「模式」来承载审批。

**与现有能力**  
permission-dialog、plan-approval-card、ask-question；产品化为三档语言与默认策略。

---

### 4.4 Review：交付预览为主、diff 次之

**目的**  
让「回来审」审的是成果，不是先读补丁。

**用户价值**  
打开交办就能读周报 / 表 / 文档；需要时再看改了哪些文件。

**主流程**

1. 交办进入「待你确认」→ Review 主视图 = **交付预览**（MD / HTML；Office 预览按仓库设计进度逐步接，不以已全部 GA 对外承诺）。  
2. 次级页签 / 折叠区：**变更明细**（文件列表 + diff）。  
3. 操作：采纳 / 部分采纳 / 打回重做 / 另存到 Wiki 或目标文件夹。  
4. 编码仓库上下文：可默认仍突出 live diff，但同一套 Review 壳。

**边界**

- 预览打不开时降级为「文件列表 + 打开本地」；不阻塞采纳流程。  
- 划选就地改（行内改）列为后做，本阶段以预览 + 评论 / 打回为主。

**与现有能力**  
ACP live diffs、To-do Review / Merge；office-preview / unified-file-preview 设计方向作为预览层演进。

---

### 4.5 非编码任务文案层（隐藏 worktree / merge）

**目的**  
同一套隔离与审阅引擎，两套人话。

**用户价值**  
整理文件夹、写调研、收件箱分诊时，不会被 git 术语劝退。

**主流程**

| 底层概念（可保留） | 非编码 UI 文案 | 编码仓库 UI |
|--------------------|----------------|-------------|
| worktree / 隔离区 | 隔离工作区 | worktree（可保留） |
| Review | 待你确认变更 | Review |
| Merge | 采纳到目标位置 | Merge |
| 看板 Done | 已交付 | 已合并 / 已交付 |

1. 检测任务工作区类型：纯文件夹 / Wiki / 调研 → 非编码文案；git 代码仓库 → 编码文案。  
2. 用户可在进阶设置查看「技术细节」。

**边界**

- 只做文案与信息架构层即可先上线，不强制重写引擎。  
- 不在非编码路径暴露 branch 名、冲突命令行，除非用户展开高级信息。

**与现有能力**  
To-dos 的 worktree → Review → Merge 流水线；加文案映射与列名。

---

### 4.6 多代理 @ / Canvas（深度能力，非新手默认）

**目的**  
保留护城河，但避免认知过载。

**用户价值**  
复杂活可以「一个主办 + 若干专家」并行；日常快问不被 16 个 agent 吓到。

**主流程**

1. 默认个人工作配置：露出 **1 个通用工作代理**；需要时再「添加专家 / @ 代理」。  
2. `@` 委托结果以**卡片 / 徽章**回流主线程，用户默认只盯主会话。  
3. Infinite Canvas：放在进阶；提供后置的新手模板（「本周工作」「调研板」——模板属后做，本阶段至少不强制空白画布当首页）。

**边界**

- 不为「通用化」砍掉多代理深度。  
- 不把 Canvas 设为新用户唯一首页。

**与现有能力**  
`@` 多代理、Infinite Canvas、统一 ACP 工具卡——完整保留，调整默认露出与导航权重。

---

### 4.7 频道与完成通知

**目的**  
人不在桌面前也能收活、看完成。

**用户价值**  
飞书 / 微信 / Telegram 来的活可以分诊进交办；做完回传同一频道。

**主流程**

1. **入站：** 频道消息 → 工作台「待分诊」或 Composer 草稿 → 用户确认「转交办」或「仅回复」。  
2. **出站：** 交办终态（完成 / 需确认 / 失败）按用户设置推系统通知与可选频道。  
3. 回传内容：短摘要 + 深链打开 Review / 会话（移动端打开轻量页）。

**边界**

- 频道侧不做完整本机 Agent；重活回桌面 / 交办。  
- 事件触发型全自动（邮件一到就跑）属后做；本阶段以「频道来活 → 人确认分诊」为主。

**与现有能力**  
已有 chat channels（飞书 / 微信 / Telegram）与 Automations；补齐与交办终态、托盘的一致产品语言。

---

### 4.8 轻量日常（快问、定时简报、分诊）

**目的**  
不是每件事都上重型多代理。

**用户价值**  
快问像聊天；早间简报像 Recap；频道分诊像收件箱，而不是每次开 Canvas。

**主流程**

| 能力 | 主流程 | 备注 |
|------|--------|------|
| **快问** | Composer 短路径，不升交办，无托盘噪音 | 可稍后「把本轮转为交办」 |
| **定时简报** | 建交办时设 schedule（如工作日 8:10）→ 产出进 Wiki 或会话 → 通知 | 复用 Automations / To-do schedule |
| **分诊** | 频道 / 收件摘要列表 → 标记交办 / 稍后 / 忽略 | 对齐 Slack Recap 的轻量价值 |

**边界**

- 定时任务若碰本地文件，标明桌面在线要求。  
- 不做「移动端假装完整桌面」。

**与现有能力**  
会话、Automations、To-do schedule、频道；收束为三种轻量路径的明确 UX。

---

### 4.9 个人 Wiki 最小可用

**目的**  
给个人工作一个稳定落点，而不是一次做完知识图谱。

**用户价值**  
交办产出能存进「我的 Wiki」；下次交办能引用；整理任务看得见。

**主流程（最小验收）**

1. **侧栏稳定入口**「知识 / Wiki」。  
2. **导入可靠**（本地 md / 文件夹；范围以当前产品进度为准）。  
3. **整理任务可见**：可从 Wiki 发起「整理本周笔记」类交办。  
4. **交办采纳可选「写入 Wiki」**。  
5. 与会话 `@` Wiki 页面作为上下文。

**边界**

- Wiki 仍在打磨：撤回 / 冲突 / 部分桌面能力可能未齐——文档不宣称已全部 GA。  
- 不对标一次性做完 Notion 全家桶；先当「个人工作记忆落点」。

**与现有能力**  
Personal Wiki（可试用、未达方案全验收）——本规格定义最小日常可用切片。

---

### 4.10 打开代码仓库时的高级能力（保留护城河）

**目的**  
门面换软后，开发者深度不丢。

**用户价值**  
同一产品：白天交办周报，晚上开仓库仍是多智能体编码工作台。

**主流程**

1. 用户打开 / 绑定 git 代码仓库作为工作区。  
2. UI 自动露出：  
   - live diff、tool cards、计划与权限（现有 ACP）；  
   - worktree / Review / Merge 原词（或与业务文案并列）；  
   - 多 coding agent `@`、Canvas 并行。  
3. 非仓库交办仍走软文案路径（对比见 scenarios S4 vs S5）。

**边界**

- 不在「个人工作配置」首页默认铺满 coding agent 选择器。  
- 不为通用化删除 ACP / 多 agent / To-do 深度。

**与现有能力**  
全部编码向能力保留，改为**上下文触发露出**。

## 5. 必先做 / 可后做 / 明确不做

### 5.1 必先做（高杠杆，贴现有架构）

1. 对话 | 交办同一 Composer；「转为交办」做大。  
2. 非编码任务文案层（隔离工作区 / 待你确认 / 采纳）。  
3. 进行中托盘 + 完成 / 待确认 / 失败通知（系统 + 可选频道）。  
4. 审批三档，默认平衡。  
5. Review 主视图 = 交付预览，diff 次之。  
6. 会改外界的交办默认走计划卡。  
7. 个人 Wiki 推到日常能用的最小集（入口、整理任务、导入、交办落点）。  
8. 交办进度叙事统一为一种「当前步骤」组件。

### 5.2 可后做

- 划选就地改交付物  
- Steer / Queue 显式切换（队列能力已有，补产品开关与文案）  
- 邮件 / 日历 / IM **事件触发** Automations  
- server / 云 worker 跑交办（桌面仅挂本地文件夹）  
- 真正的「项目」对象（指令 + 记忆 + 默认目录 + 默认 agent）  
- 插件包（skill + 连接器 + 子代理）  
- Canvas 新手模板  
- 交付物 Checkpoint / 版本（非仅 git）  
- 全局热键 + 迷你窗（选中文本送进 CodeG）  
- 个人工作配置下默认只露 1 个通用 agent  

### 5.3 明确不做（本阶段）

- 为「通用」砍掉多代理 / To-do / ACP 深度  
- 再叠互不共享上下文的新模式  
- 移动端承诺与桌面同等的本机文件代理  
- 把企业 SSO / SCIM 当成本阶段主轴（已有独立调研）  
- 编造或对外承诺未 GA 的 Wiki / Office 预览为已完成

## 6. 成功指标（定性）

不编造基线数字；用可观察的体感与验收故事。

| 维度 | 定性成功信号 |
|------|----------------|
| **入口** | 新用户不经过「先选模式」就能完成一次快问和一次交办 |
| **交办可信** | 用户敢离开屏幕；靠托盘 / 通知回来，而不是轮询会话 |
| **文案友好** | 非编码交办全程可不出现 worktree / merge；编码路径仍完整 |
| **审批疲劳** | 默认平衡档下，用户不再抱怨「每一步都要点」；敏感写操作仍有闸 |
| **Review** | 回来先看交付预览就能决定采纳 / 打回；diff 为可选项 |
| **双栖** | 同一人可在一天内完成「周报交办」与「开仓库多代理改代码」无需换产品 |
| **Wiki 落点** | 至少一条交办产出能稳定写入 Wiki 并在下次被 @ 引用 |
