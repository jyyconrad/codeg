# Wiki 目录阅读与项目元数据

日期：2026-09-14。当前个人 Wiki 只有一套数据，正文统一使用 `wiki/`，运行状态使用 `wiki-state/`。本说明优先于旧稿的版本目录与“文件树仅高级入口”安排。

## 阅读方式

个人 Wiki 默认进入首页，左侧显示目录，正文复用现有阅读器。目录选择、正文内部链接和浏览器历史共用 URL 状态；工作、能力、资料和处理记录仍保留专用入口，概览继续提供统计。

文件本身也是交付物：根目录 `index.md`、各目录索引和元数据页使用 Markdown 与目录内链接。Obsidian 通过“打开文件夹为仓库”选择整个 Wiki 目录，再打开 `index.md`；不用导入插件，也不依赖 Codeg 数据库显示正文。应用显示实际解析后的路径，服务器模式注明该路径位于服务器，需要复制或同步到本地才能用本地 Obsidian 打开。

采用 Obsidian 官方支持的[文件夹仓库](https://obsidian.md/help/manage-vaults)、[内部链接](https://obsidian.md/help/links)及 [YAML 属性](https://obsidian.md/help/properties)。不修改 `.obsidian` 配置。

## 代码输入的元数据

项目关联使用既有的 `(vault_id, db_instance_id, root_folder_id)` 绑定，名称和路径只是属性，不作为跨项目合并依据。

- 项目页：绑定标识、数据库实例标识、根目录及其文件夹成员。
- 文件夹页：文件夹标识、父目录/根目录关联、名称、别名、路径和可用状态。
- Git 信息：仓库根目录、公共 Git 目录、分支、HEAD、detached/unborn 状态和已去凭据的 remote。普通目录、失效路径、Git 探测失败分别记录。

宿主通过类型化结构收集事实，导出到 `metadata/projects/` 与 `metadata/folders/`，属性保持标量和列表，正文可阅读、项目与文件夹互相链接。采集只使用数据库和本地 Git，不请求网络，不把账户凭据写入笔记。Git 快照有采集时间，不等同于会话发生时的历史状态。

根据用户后续明确的简化要求，归纳任务运行时取得素材路径与相关项目元数据，Agent 自主读取整理。排队和重试不固定素材版本，不要求回传哈希、逐行阅读记录或行号证据，也不为长材料额外运行多轮切片摘要。统计查询不触发 Git 扫描。代码负责补来源标识、材料路径、原始地址及项目关联；读取时检查源文件当前是否存在，缺失来源保留地址并标记，不影响阅读已经生成的 Wiki 正文。

已有内部摘要去重和输出文件写入保护保留，用于避免重复归纳和覆盖人工修改；它们不是模型输入证明，也不增加前置模型调用。

## 派生文件与人工编辑

`wiki_refresh_library` 刷新目录索引和元数据，不调用模型，也不自动启用会话采集。后台笔记生成后也刷新目录，因此 Obsidian 可以持续阅读。目录入口只指向实际存在的 Markdown 文件；维护文件与原始记录保留在高级浏览入口。目录索引不作为待归纳素材，避免自动整理自身导航。

代码维护的文档带生成内容校验标记。标记之后的人工补充原样保留；人工修改了生成区域或属性时，停止刷新该文件并报告路径。无标记的用户文件不覆盖，仅精确等于已知旧首页模板时升级。文件写入校验相对路径、拒绝符号链接穿越，使用同盘临时文件替换。

## 验收

默认目录首页、点击目录/正文链接、前进后退、搜索和刷新均可用；有效 Wiki 路径可复制。新增或删除笔记后，刷新更新索引。普通目录、Git 根仓库和 worktree 的元数据表达准确；remote 凭据剥离；人工补充保留、人工改写生成部分得到提示。Markdown 文件在脱离应用后仍有可用目录链接。

## 统一目录的本机迁入

按用户要求直接复制现有资料并更新目录指针，保留资料库、来源、项目和任务身份；不清空现有数据，不新增多版本迁移框架。当前有效配置为 `wiki_settings`，目录标记只标识 Codeg Wiki，不判断数据版本。原目录及数据库快照保留到用户验证通过后再清理。

旧程序仍按原路径规则运行，因此迁入期间只暂停其 Wiki 自动写入，普通聊天继续使用。新代码通过唯一配置读取统一目录；原文、笔记正文、归纳记录及原件均保留。
